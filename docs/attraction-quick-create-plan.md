# 景点新增链路优化计划

- 状态：待实施。本次仅提交计划，不包含功能改动或生产部署。
- 代码基线：`d164d12`。
- 目标：减少重复选择和跨页签、跨菜单操作，保留现有完整编辑能力与数据契约。

## 1. 现状与问题

当前完整景点编辑页有 8 个页签：基础资料、景点展示、线上预览封面、名导讲解、讲解点、参观服务、文史内容、关联目的地。它们并非全部必填，但常用新增字段分散在多个位置，容易让操作人员误认为必须逐页完成。

已核对的具体问题：

1. 名称、城市、类型在基础资料，主图和简介在景点展示，目的地关联又在独立页签。
2. 城市 ID 与城市名称仍需分别填写，存在重复劳动及数据不一致风险。
3. 已有“按目的地分组 → 新增景点”入口，但目前只预选目的地，没有带入其城市和国家。
4. 音频管理位于另一个菜单，上传讲解时需要再次查找、选择刚新增的景点。
5. 缺少“保存并新增下一个”，连续录入相同城市的景点需要重复操作。

现有可复用能力：智能填写、景点保存与目的地关联同步、未保存修改保护、公开状态核验、景点批量发布，以及编辑返回列表原位。

## 2. 目标流程

### 第一期：已有城市、目的地时的常规录入

```text
选择目的地分组 → 新增景点
                     ↓
           自动带入城市、国家、目的地
                     ↓
       单页填写名称、类型、主图、简介
                     ↓
      保存并返回 / 保存并继续 / 保存并新增下一个
```

从普通景点列表新增时，在同一页选择城市、目的地，再完成录入，不需要手写 ID 或切换页签补关联。

可验证的目标：

- 常规新建在一个页面内完成基本资料、关联及保存。
- 从目的地入口新建时，不重复选择城市、国家和目的地。
- 连续录入同一城市的景点时，不返回列表、不重复选择相同上下文。
- 不将完整资料维护、音频上传等工作强制变成基础录入的前置步骤。

### 第二期：需要音频的景点

在当前景点页直接添加线上预览或名导讲解音频，自动关联当前景点，无需切换菜单重新查找。页面内部可以分多次请求完成，但对操作人员保留明确的保存进度及失败状态。

## 3. 第一期范围

### 3.1 快速新增单页

- [ ] 提供快速新增视图，首屏集中显示景点名称、所属城市、关联目的地、主图、简介、类型六项常用信息。
- [ ] 新建类型默认“景点”，可切换为“博物馆”。
- [ ] 默认未发布，沿用现有 `unpublished` 状态，不引入新的数据库状态值。
- [ ] 必填校验沿用现有后台及 API 契约；不因高级资料未填写而新增拦截。
- [ ] 标签、希腊语名称、独立封面、讲解点、参观服务、地图、视频、文史等保留在更多资料或完整编辑入口。
- [ ] 保留原有完整编辑页及其能力，不把 8 个页签改成另一个必须逐步点击的长向导。
- [ ] 保留现有智能填写；生成结果作为待核对草稿，不自动发布，也不伪造图片、音频或播放状态。

### 3.2 城市与目的地自动带入

- [ ] 城市使用可搜索下拉，读取现有城市主数据；选择后同步写入 `city` 与 `cityName`，国家按主数据推导。
- [ ] 从目的地分组新建时，预选入口目的地，并从其 `cityId`、关联城市主数据带入城市与国家。
- [ ] 从普通列表新增时，支持在同页选择已有目的地；同城存在多个目的地时展示选择，不自动全部勾选。
- [ ] 目的地缺少有效城市时给出明确提示，允许人工选择，不猜测或新建主数据。
- [ ] 切换城市或目的地发现关系不一致时提示确认，不静默清空已选关联。
- [ ] 自动推导只用于新建默认值，不覆盖历史景点已有资料。
- [ ] 不自动创建城市、目的地、分类；缺少主数据时提示使用已有管理入口，并沿用未保存修改保护。

### 3.3 一次保存完成关联

- [ ] 复用现有景点保存与目的地关联接口，操作人员无需再进入目的地管理补一次关联。
- [ ] 资料保存、关联同步、公开状态核验分别呈现结果，不把其中一项成功误报为全部成功。
- [ ] 首次创建成功后立即保留服务端返回的景点 ID；关联失败或重试时复用该 ID，不重复 POST 创建景点。
- [ ] 保存或关联未全部完成时保留当前表单，不清空、不自动进入下一条，也不自动重试不确定写入。
- [ ] 发布保持显式操作，并集中展示现有公开展示条件及核验结果；不擅自修改服务端发布、计价或权益规则。
- [ ] 没有音频不能被误报为可播放、可售讲解；资料展示与讲解可用性分别表达。

### 3.4 保存并新增下一个

- [ ] 增加“保存并新增下一个”，仅在本条资料和关联全部保存成功后进入下一条。
- [ ] 下一条只保留城市、目的地、类型等录入上下文，国家继续由主数据推导。
- [ ] 清空景点 ID、名称、简介、图片、音频、视频、讲解点、文史等内容，以及本条校验与核验状态。
- [ ] 下一条恢复未发布默认状态，不继承上一条发布状态、付费权益或资源关联。
- [ ] 沿用当前编辑会话的上下文，不新增浏览器跨会话持久化。
- [ ] 保留“保存并返回”“保存并继续编辑”原有语义；返回列表仍保持分页、筛选、分组页码及横纵滚动位置。

## 4. 第二期范围：景点页内添加音频

- [ ] 在景点编辑页提供“添加线上预览音频”“添加名导讲解音频”入口。
- [ ] 未保存的新景点先明确保存为未发布记录并取得 ID，再上传及关联音频。
- [ ] 自动绑定当前景点、按入口预选类别，不重复搜索景点。
- [ ] 复用现有私有上传、试听生成、时长、收听规则与发布接口，不引入新的文件存储体系。
- [ ] 讲解点、路线或专辑按实际需要选择，不因景点继承而误关联其他对象。
- [ ] 试听时长、收听规则、付费权益仍按现有契约校验，不自动设为免费或发布。
- [ ] 上传成功但关联失败时保留上传结果和已创建音频 ID，提供明确恢复入口，避免重复上传、重复创建。
- [ ] 独立音频管理继续保留，用于检索、批量维护及复杂资料编辑。

第二期需单独确认实施，不与第一期捆绑发布。

## 6. 验收与测试计划

### 第一期验收

1. 从有效目的地分组新增，城市、国家和目的地正确带入，无需手填城市 ID。
2. 从普通列表选择城市后，ID 与名称一致；同城多个目的地不会被自动全部关联。
3. 目的地城市失效、主数据缺失、切换关联产生不一致时有提示，用户选择不会被静默清空。
4. 常规新增无需切换页签；更多资料与原完整编辑仍可访问，既有数据不会被隐藏后清空。
5. 名称或简介等既有必填校验正确；新建默认未发布，不自动改变商品或讲解权益。
6. 创建成功、关联失败后仍保留景点 ID 和表单；重试不重复新增，不进入下一条。
7. 保存成功后新增下一条，仅保留约定上下文，不残留上一条资源、内容、发布状态或内部 ID。
8. 取消、未保存确认、保存并继续、连续新增后返回列表均符合原有行为；列表原位置不回退。
9. 智能填写失败或保存失败时仍保留人工输入，不误报完成。
10. 桌面和 390px 窄屏可完成常规新建；按钮不被返回顶部控件遮挡。

### 回归方式

- 新增专门的快速新增回归脚本（建议 `scripts/test-attraction-quick-create.mjs`，待实施时创建）。
- 运行现有 `scripts/test-admin-editor-return.mjs`、`scripts/test-attraction-destination-links.mjs` 及受影响的契约测试。
- 所有写入测试仅在复制模块和数据的临时 `SY_STORAGE=json` 服务中执行，不对本地真实 MariaDB 或生产做演练。
- 在临时目录构建并浏览器验证，避免测试构建清空现有 `dist` 媒体或混入不相关生成文件。
- 运行 `git diff --check`，逐项确认修改范围。

### 第二期追加验收

上传音频自动关联正确、试听及权益契约不变、失败恢复不重复上传或创建、无音频时不误报可播放，以及独立音频管理不回退。
